Чем считать эмбеддинги

риск: средний бэкенд БД инфра · деньги

У Groq эмбеддингов нет — проверил на первоисточнике, страницы Embeddings в console.groq.com не существует (упоминания на сторонних сайтах не подтверждаются). Значит нужен отдельный провайдер. Выбор напрямую бьёт по счёту Railway: локальная модель — это +2 GB RAM на воркере ≈ $20/мес при тарифе $10/GB. Размерность фиксируется в миграции, менять потом = пересчитывать все векторы.

Как это выглядит в коде и почему размерность важна
# app/analysis/embeddings/base.py — провайдер абстрактный, dim берётся из настроек
class EmbeddingProvider(Protocol):
    dim: int
    async def embed(self, texts: list[str]) -> list[list[float]]: ...

# миграция фиксирует размерность НАВСЕГДА:
sa.Column("embedding", Vector(settings.EMBEDDING_DIM))
op.execute("CREATE INDEX ... USING hnsw (embedding vector_cosine_ops) "
           "WITH (m=16, ef_construction=64)")

# Обе кандидатуры (1024 и 1536) < 2000 — индексируются напрямую.
# 3072-мерные модели потребовали бы halfvec — поэтому их не рассматриваем.

05

Как запускать Telethon

риск: высокий бэкенд инфра · деньги

Это user-session, не бот — то есть твой личный аккаунт. Telegram наказывает за частые перелогины нарастающим FloodWait: семь секунд превращаются в четыре часа за час экспериментов. Поднимать клиент внутри Celery-таски = логиниться на каждый прогон.

Ключевой фрагмент: курсор и защита от FloodWait
async with TelegramClient(StringSession(SESSION), api_id, api_hash) as c:
    c.flood_sleep_threshold = 60   # до 60с Telethon спит сам
    for src in active_sources:
        try:
            async for m in c.iter_messages(src.entity,
                                           min_id=cursor.last_item_id,   # ← не читаем прочитанное
                                           reverse=True):
                await save_raw_item(m)
                cursor.last_item_id = m.id
        except FloodWaitError as e:
            if e.seconds > 300:
                await pause_source(src, e.seconds)   # НЕ ретраим агрессивно
                continue
            await asyncio.sleep(e.seconds + 5)
06

Чем ходить в GitHub API

риск: низкий бэкенд

Ограничения жёсткие: search — 30 запросов/минуту, core — 5000/час, search отдаёт максимум 1000 результатов на запрос. Спасает то, что 304 Not Modified не тратит лимит — значит ETag-кэш обязателен, и библиотека должна его уметь.

Почему GraphQL для массового добора метаданных
# REST: 50 репозиториев = 50 запросов = 50 единиц лимита
# GraphQL: 50 репозиториев = 1 запрос ≈ 1 point (ceil(nodes/100))
query {
  r0: repository(owner:"langchain-ai", name:"langchain") {
    stargazerCount forkCount pushedAt
    licenseInfo { spdxId }
    latestRelease { tagName publishedAt }
  }
  r1: repository(...) { ... }   # ... до 50 алиасов
  rateLimit { remaining resetAt }
}

Модель Groq для массового слоя

риск: низкий бэкенд деньги

Важное ограничение, проверенное на docs Groq: строгий JSON-схемой режим (strict: true) поддерживают только openai/gpt-oss-20b и openai/gpt-oss-120b. У остальных моделей strict молча игнорируется — то есть валидный JSON не гарантирован, а нам он нужен на каждом сообщении.
