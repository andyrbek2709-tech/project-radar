=== ШАГ 1. Том для Postgres ===
Сейчас у Postgres нет тома: база живёт в эфемерном слое контейнера и пропадёт
при любом рестарте. Подключение тома само по себе требует рестарта, поэтому
текущие 384 сырых записи будут потеряны. Это нормально: находок ноль, а сырьё
пересоберётся автоматически в ближайшие два часа.

Railway → проект → сервис Postgres → Settings → Volumes → Add Volume.
Mount path: /var/lib/postgresql/data
Дождись, пока сервис снова станет Active.

Проверка: Postgres → Deployments → View Logs. Ожидается инициализация нового
кластера («database system is ready to accept connections»). Если вместо этого
ошибка про непустой каталог — скажи мне, не чини сам: за это отвечает
переменная PGDATA=/var/lib/postgresql/data/pgdata, она должна быть задана.

Полный промпт 
Ты работаешь в браузере Chrome. Я уже залогинен в Railway и в само приложение.
Проект называется Project Radar. Публичный адрес фронта:
https://web-production-1aaaa.up.railway.app

Задача: проверить, что деплой поднялся и переменные окружения введены верно.
Если найдёшь расхождение — поправь его прямо в дашборде Railway.

=== ПРАВИЛА ===
1. Значения секретов не выводи в ответ ни целиком, ни кусками. Это ADMIN_PASSWORD,
   SECRET_KEY, GITHUB_TOKEN, GROQ_API_KEY, OPENAI_API_KEY, POSTGRES_PASSWORD,
   TELEGRAM_API_HASH, TELEGRAM_SESSION_STRING, DATABASE_URL, REDIS_URL.
   Про них пиши только: «задано», «пусто», «совпадает с api», «НЕ совпадает с api».
2. Не удаляй сервисы, тома и переменные. Не жми Delete ни на чём.
3. Менять значение переменной можно — но сначала напиши в ответе, что именно меняешь,
   на что и почему. Redeploy делай только после правки и скажи, какой сервис перезапустил.
4. Если страница не загрузилась — один повтор, потом опиши, что увидел, и иди дальше.
5. В конце дай сводный отчёт по форме из последнего раздела.

Сверь наличие ключей по списку ниже. Значения секретов не выводи.

  ADMIN_PASSWORD = (непустой)

web — обязаны быть:

=== ШАГ 6. Start Command у каждого сервиса ===
Settings → Deploy → Custom Start Command. Сверь дословно:
  api:       sh -c 'alembic upgrade head && exec uvicorn app.main:app --host 0.0.0.0 --port $PORT'
  worker:    celery -A app.tasks.celery_app worker --loglevel=info --concurrency=2 --max-tasks-per-child=200
  scheduler: celery -A app.tasks.celery_app beat --loglevel=info --scheduler redbeat.RedBeatScheduler
  telegram:  python -m app.collectors.telegram_runner
  web:       node server.js

У api команда обязана быть обёрнута в sh -c: Railway выполняет Custom Start Command
без шелла, и без обёртки && и $PORT не раскроются.
Хост обязан быть 0.0.0.0, а не :: — healthcheck Railway ходит по IPv4.

=== ЛЕЧЕНИЕ A. Прокси отдаёт «Backend недоступен» (502) ===
Это значит: web поднялся, но не достучался до api. Проверь по порядку и останавливайся,
как только нашёл причину:
  1. web → Variables → API_URL. Должно быть ровно
     http://${{api.RAILWAY_PRIVATE_DOMAIN}}:8000
     Частые ошибки: https вместо http, публичный домен вместо приватного,
     другой порт, хвостовой слэш.
  2. api → Variables → PORT. Должно быть 8000. Если переменной нет — добавь.
  3. api → Deployments. Если не Active — открой логи, это и есть причина.
  4. api → Settings → Networking. Если у api выдан публичный домен, у него есть
     Target port. Railway фиксирует его при ПЕРВОМ деплое и часто ставит 8080 —
     должно быть 8000.
После правки: Redeploy сервиса web, подожди, пока станет Active, и повтори ШАГ 2.

=== ЛЕЧЕНИЕ B. 401 / Not authenticated ===
Пароли у web и api разошлись. Открой Variables у обоих и сравни ADMIN_USERNAME
и ADMIN_PASSWORD. Значения не выводи — скажи только, совпадают или нет.
Если не совпадают: скопируй значение из api в web (не наоборот), Redeploy web,
повтори ШАГ 2.

=== ЛЕЧЕНИЕ C. HTTP 500 ===
api жив, но упал внутри. Открой api → Deployments → View Logs, последние 30 строк.
Ищи одно из двух:
  - «could not translate host name» / «connection refused» / пустой DATABASE_URL →
    известная ловушка Railway: ссылка ${{Postgres.DATABASE_URL}}, сохранённая ДО того,
    как сервис Postgres был создан, резолвится в пустую строку навсегда.
    Лечение: открой api → Variables, удали строку DATABASE_URL, сохрани,
    заново добавь DATABASE_URL = ${{Postgres.DATABASE_URL}}, сохрани, Redeploy api.
  - ошибка alembic / «relation does not exist» → миграции не прошли.
    Приведи текст ошибки в отчёте, сам не чини.

=== ЛЕЧЕНИЕ D. Application failed to respond ===
Не поднялся сам web. Открой web → Deployments → View Logs.
Проверь RAILWAY_DOCKERFILE_PATH = web/Dockerfile и Start Command = node server.js,
а также Settings → Networking → Target port = 3000. Приведи последние 20 строк логов.

Ссылки, которые можно открыть самому

Всё это открывается в обычной вкладке и возвращает JSON — тот же origin, CORS не мешает. Первая ссылка проходит весь путь целиком: браузер → web → приватная сеть → api → Postgres. Если она отдала JSON, остальное можно не смотреть.

Адреса /api/proxy/health не существует — и это не поломка. Прокси фронта подставляет префикс /api/, а /health у бэкенда лежит вне его. Проверять живость надо через /api/proxy/stats/dashboard.

Эталонные блоки переменных

Для RAW Editor в Railway. Секретные значения оставлены плейсхолдерами — подставь свои. Полная версия с обоснованием каждого числа — в docs/RAILWAY_VARIABLES.md.

web — единственный публичный сервис

Самый частый источник 502. ADMIN_* здесь обычные переменные, не NEXT_PUBLIC_*: Basic-auth подставляет серверный прокси, в браузер креды не уходят.

web

API_URL=http://${{api.RAILWAY_PRIVATE_DOMAIN}}:8000
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<тот же, что в api>
NODE_ENV=production

api — критичная часть

Без PORT=8000 адрес api в приватной сети непредсказуем, и web его не найдёт.

Start Command — дословно

Railway выполняет Custom Start Command без шелла. У api обёртка sh -c обязательна, иначе && и $PORT не раскроются.

api
sh -c 'alembic upgrade head && exec uvicorn app.main:app --host 0.0.0.0 --port $PORT'
worker
celery -A app.tasks.celery_app worker --loglevel=info --concurrency=2 --max-tasks-per-child=200
scheduler
celery -A app.tasks.celery_app beat --loglevel=info --scheduler redbeat.RedBeatScheduler
telegram
python -m app.collectors.telegram_runner
web
node server.js
05

Четыре ловушки, на которых этот деплой уже спотыкался

1. Ссылка на Postgres, сохранённая слишком рано

${{Postgres.DATABASE_URL}}, сохранённая до того, как сервис Postgres был создан, резолвится в пустую строку — и остаётся пустой навсегда, даже когда сервис появился. Лечение: удалить переменную, сохранить, добавить заново, сохранить, Redeploy.

2. Target port домена фиксируется первым деплоем

Railway запоминает порт при самом первом деплое и часто ставит 8080. У api он должен быть 8000, у web — 3000. Правится в Settings → Networking у самого домена, а не в переменных.

3. Custom Start Command без шелла

Команда api содержит && и $PORT — без обёртки sh -c '...' они попадут в uvicorn как литералы и контейнер не стартует.

4. Хост uvicorn — только 0.0.0.0

Healthcheck и публичный прокси Railway ходят по IPv4. С --host :: контейнер получается IPv6-only, healthcheck не доходит, и деплой падает через пять минут без единой строки ошибки в логах приложения.
